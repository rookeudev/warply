# Warply 0.2.1 Windows acceptance checklist

Use a Windows VM with console access and a snapshot before testing persistent network blocking. Automated checks and the aborted WFP validation transaction do not replace these tests.

## Setup and everyday operation

- Clean first launch without WireGuard: automatic account creation; one installation confirmation; approved official installation; disconnected/Ready afterward. Test decline, failed installation, and Check again.
- Clean first launch with WireGuard: no file picker or import setup; account created; Ready. Test network failure, rate limit/API failure, Try again, and Advanced import fallback.
- Second launch: saved account retained, no registration or update request with default settings; one helper UAC approval per session, none on successive toggles. Cancel UAC: clear error, no repeated background prompts; explicit retry can request approval again.
- Launch from Start, including manual launch with tray-on-logon enabled. Check startup loading, Start shortcut, notifications, tray statuses, and autostart after upgrading a previous elevated task.
- Launch normally and from an elevated installer/shortcut: GUI must run unelevated. Also test UAC approval with another administrator's credentials; profile must remain owned by the original desktop user.
- Connect and disconnect repeatedly. Verify encrypted service storage under ProgramData, cleanup after successful stop, and no plaintext temporary configs.

## Verification and recovery

- Real IPv4/IPv6 WARP traffic: green only after both probes and local route/DNS checks succeed.
- Block IPv4 only, IPv6 only, DNS inspection, or just the trace endpoint: no stale green, precise unverified status; OFF remains available. A trace-only outage must not repeatedly restart the service.
- Start another VPN: clear conflict, no misleading green. Unsupported inspection must show unknown rather than success.
- Change Wi-Fi/Ethernet, sleep/resume, temporarily lose internet, and stop the tunnel service: bounded reconnection; after exhaustion show recovery error and allow Restore internet.
- Disconnect or Restore internet while a connection/check is pending: old results cannot verify a newer session and the final service must be stopped.

## Persistent kill switch

- Enable while disconnected, connect, then stop/crash the tunnel service: ordinary IPv4/IPv6 web traffic stays blocked, including after GUI/helper termination and reboot. Inspect the documented WireGuard, loopback, DHCP, and IPv6 discovery exceptions separately.
- Launch again while blocked: reconcile the current tunnel interface; reconnect using the protected numeric endpoint cache. Test stale/missing cache and recovery instructions.
- Explicit OFF, Restore internet, normal quit, and uninstall remove only Warply filters and restore ordinary networking subject to other firewall rules. Existing unrelated firewall rules must remain intact.
- Test emergency `warply.exe --restore-internet` and temporarily unavailable WireGuard.exe; never replace WireGuard with an untrusted executable for connection.

## Storage and privacy

- Verify ordinary other users cannot read the profile or service copy; inspect user/SYSTEM and SYSTEM/Administrators DACLs.
- Corrupt a backed-up encrypted profile: no silent overwrite, registration, or plaintext fallback. Reset cancellation/network failure preserves the old account.
- Import/export rejects links, hard links, UNC/remote paths, alternate streams, and ambiguous names. Explicit export warns about the private key.
- Local diagnostics/copy contain no private key, configuration, IP, user/computer/network name, or raw commands. No report upload or persistent diagnostic log occurs.
- With automatic updates disabled, disconnected later launch makes no registration, trace, or GitHub request. Opt-in checks occur at most daily; manual checks still work.

## Updates, installer, and usability

- Valid higher signed release installs only after confirmation. Reject a bad signature, wrong signed version, foreign URL, downgrade, or unexpected redirect before executing anything.
- Cancel update, fail download, fail verification, and fail installer launch: preserve profile; launch failure attempts to restore prior connection. Test interrupted installation and previous-executable recovery without claiming power-loss rollback.
- Upgrade and uninstall with protection active: clear protection before removing recovery software, retain profile on upgrade, restore Start shortcut, and do not reset other firewall rules.
- English/Czech, light/dark, small window scrolling, keyboard focus/Tab/Escape, screen-reader labels, reduced motion, and Windows high contrast.

## Checks performed during development

TypeScript production build, ESLint, Rust formatting/clippy, Rust unit/storage tests, mocked browser flows, and a native Windows WFP transaction validation were exercised. The native preflight aborts its transaction and does not turn on live blocking. Real tunnel/crash/reboot/installer acceptance above remains necessary before claiming full runtime validation.

## 0.2.2 hotfix acceptance

Upgrade an affected 0.2.1 installation without resetting its profile. Connect/disconnect and confirm the file-permissions error is gone. Verify ProgramData service-folder and service-file permissions remain SYSTEM/Administrators only after repeated saves and reconnects.

## 0.2.4 recovery acceptance

- Upgrade installed 0.2.1 with the ordinary new installer: repair mode must avoid invoking its broken uninstaller and preserve the profile. Test /UPDATE /P and standard interactive flows separately.
- Uninstall with app closed and no service/protection: success, including repeated headless cleanup. Missing service storage must not create a folder or trigger ACL errors. Confirm distinct service/WFP/storage/elevation messages on actual failures.
- Upgrade/reinstall, connect, leave a stopped service after a failed start, then reconnect: the stale fixed service is removed before installation. Unrelated services are untouched.
- Delete/unavailable WireGuard.exe during an active tunnel: OFF must remain enabled. Cancel connection while a request is pending and confirm final service is stopped.
- Stop the privileged helper: show unknown protection, disable unsafe kill-switch edits, and allow explicit Restore internet to restart it without background UAC loops.
- Diagnostics with missing/corrupt profile, absent adapter, or inaccessible service: show a partial redacted report. Run again with a failure: old report must disappear. Verify CLI --diagnostics needs no elevation and does not expose keys, addresses, user/network names or raw logs.
